# Публикация и обновление контента

## Что уже подготовлено

Приложение читает публичную настройку `baseUrl` из `app/WallpaperWidget/Data/remote-content.json`. Этот URL не содержит ключей доступа: пользователям разрешено только читать опубликованные файлы.

При смене публичного адреса Cloudflare потребуется изменить только этот файл:

```json
{
  "baseUrl": "https://content.example.com/wallpapers/"
}
```

Адрес должен указывать на каталог, в корне которого находится `manifest.json`.

## Полный цикл выпуска

1. Обновить мастер-таблицу и положить новые оригиналы в `content/source-images/`.
   В пользовательских текстах не должно быть маркеров `[1]`, `[2]` и подобных. URL хранятся в колонке `Sources`, по одному на строку: `Краткое название | URL` либо в совместимом служебном формате `[1] URL`.
2. Из папки `publisher` запустить `./publish.ps1 -ValidateOnly`.
3. Исправить ошибки из `publisher/state/reports/latest-validation.json`.
4. Запустить `./publish.ps1`.
5. Загрузить содержимое `content/publish/` в Cloudflare с сохранением структуры путей.
6. Сначала загружать `assets/` и `catalogs/`, последними — `manifest.json` и `manifest-aesthetic.json`.
7. Проверить оба публичных manifest-файла в браузере. Ручное действие от пользователей не требуется.

Publisher создаёт две коллекции:

- `All places` — все строки листа `Export`;
- `Visual highlights` — только строки, где `Aesthetics = Cool`.

При первом запуске пользователь выбирает коллекцию. Выбор сохраняется локально, но его можно изменить позднее в настройках виджета. Общие изображения между коллекциями повторно не скачиваются.

В зависимости от выбранного режима приложение автоматически или по кнопке `Check now`:

1. загружает маленький manifest выбранной коллекции без использования устаревшего кеша;
2. сравнивает `contentVersion` с активной локальной версией;
3. строит план, показывает количество изменений и дополнительный объём;
4. после подтверждения скачивает только отсутствующие файлы;
5. возобновляет незаконченные `.partial`-файлы через HTTP Range;
6. проверяет размер и SHA-256;
7. сохраняет каталог и изображения в `%LOCALAPPDATA%/EarthWallpaper/content/`;
8. переключает активную версию только после успешной проверки всех файлов;
9. сразу перечитывает каталог в работающем виджете.

Если интернет пропал, файл повреждён или Cloudflare недоступен, приложение продолжает использовать предыдущую версию.

## Что перезаписывается

- `manifest.json` и `manifest-aesthetic.json` — при каждом успешном выпуске.
- `publisher/state/reports/latest-validation.json` — при каждом запуске publisher.
- ежедневные `.jsonl`-логи — дополняются новыми строками.

Каталоги с версией в имени, изображения с хешем в имени и индивидуальные отчёты запусков не перезаписываются. Одинаковое содержимое повторно не копируется.

## Где смотреть журналы

Publisher:

- `publisher/state/logs/` — техническая последовательность событий;
- `publisher/state/reports/latest-validation.json` — текущие ошибки и предупреждения;
- `publisher/state/reports/run-*.json` — история выпусков.

Приложение:

- `%LOCALAPPDATA%/EarthWallpaper/logs/app-YYYY-MM-DD.jsonl`;
- `%LOCALAPPDATA%/EarthWallpaper/logs/content-update-YYYY-MM-DD.jsonl`;
- журналы старше 14 дней удаляются автоматически;
- фиксируются проверка версии, успешная установка и тип ошибки, но не URL с параметрами и не содержимое файлов.

## Настройка кеша Cloudflare

- оба manifest-файла: небольшой TTL или `no-cache`, чтобы клиенты быстро замечали обновление.
- `catalogs/*` и `assets/*`: длительный TTL (`public, max-age=31536000, immutable`), поскольку имя меняется вместе с содержимым.

## Безопасное удаление старых файлов

На первом этапе старые catalogs/assets лучше не удалять вообще. Позднее можно добавить команду очистки, которая сохраняет текущую и несколько предыдущих версий. Автоматическая очистка намеренно не включена в publisher, чтобы случайно не удалить файл, который ещё нужен клиенту.
